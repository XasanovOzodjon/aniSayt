# Watch Party sync lives on Django Channels; faces are a WebRTC mesh

A Watch Party is one Episode, one clock, in-room chat, and optional live faces. Playback state (play/pause/seek, buffering, host vs shared control) is stored on the WatchParty row and broadcast over Django Channels. `REDIS_URL` is the production channel and presence store; in-memory is only a single-process fallback. Live faces and voice are a browser mesh: Channels only forwards WebRTC signals. STUN is enough on one LAN; different networks need TURN (`TURN_URL` / `TURN_URLS` + username/credential). We rejected a media SFU (LiveKit and similar) because it would add a second runtime for eight peers who are already watching the same HLS stream. An idle Watch Party (Episode not watched for four hours) closes on the next access or heartbeat ping; a currently playing room with members stays open. We rejected a separate cron worker because the existing ping already hits `get_open`.
